# Registro de decisiones técnicas y contradicciones resueltas

Precedencia aplicada (README §6): **seguridad/ley/licencia > evidencia científica > README > PRD > arquitectura/contratos > UX > ejemplos.** Cada decisión indica si es reversible.

| ID | Tema | Decisión | Motivo / documentos | Reversible |
|---|---|---|---|---|
| D-01 | Estructura del repositorio | Se usa la de doc 15 §D (`apps/`, `services/api`, `packages/fse`, `packages/contracts`, `database/`, `tests/`). | Doc 03 y doc 15 coinciden; doc 06 §3 propone otra (`backend/`, `scientific_engine/`) y él mismo pide mantener *una* estructura canónica. | Sí |
| D-02 | Migraciones | SQL versionado en `database/migrations` + ejecutor propio (`app/db/migrate.py`) con checksum, en lugar de Alembic. | Doc 05 §9 pide SQL en migraciones; doc 03/06 sugieren Alembic. SQL plano es compatible con Supabase CLI y con PostgreSQL local. Acceso a datos con SQLAlchemy 2 (doc 06). | Sí |
| D-03 | Columnas + `body` JSONB | Cada tabla tiene columnas tipadas (FK, CHECK, únicos, estado, revisión) y un `body` JSONB validado por los modelos Pydantic del FSE. | Doc 05 §14.1 permite JSONB para estructuras variables; así BD y motor comparten un único contrato. | Sí |
| D-04 | Protocolos | Tabla `protocols` con etapas en JSONB; unifica `cooling_profiles` + `protocol_stages` del doc 05. | Doc 05 §14.3 pide no crear tablas redundantes por nombres conceptuales. | Sí |
| D-05 | Catálogo sin revisar | El seed crea todo en `draft` y una publicación `0.1.0-dev+unreviewed` marcada `contains_unreviewed_content=true`. La API la sirve en desarrollo con un aviso visible y **la rechaza en producción (503)**. | Doc 05 §9 (todo nace en borrador) vs. PRD (P0 debe ser usable). No se aprueba nada en nombre del propietario (doc 01 §9). | Sí |
| D-06 | Ciclo esquemático | Sin protocolo publicado, el FSE devuelve `thermal_history=[]` y un `schematic_cycle` que solo contiene las cifras del estudiante (temperatura objetivo y tiempo). Calentamiento/enfriamiento/baño se muestran **sin cifra** y «no a escala». | Doc 04 §13.3: un perfil sin cinética medida solo puede ser representación didáctica; no inventar velocidades ni temperaturas de baño. | Sí |
| D-07 | Límite físico 1538 °C | Se registra el punto de fusión del hierro puro como **límite de bloqueo** (evidencia `ev_fe_melting_point`, estado `draft`, fuente Callister, localizador pendiente). Bloquear es la alternativa segura; nunca produce un resultado. La interfaz muestra que el límite está pendiente de verificación. **No pude verificarlo en línea** (la red del entorno bloqueó PubChem). | README §6 (preferir lo seguro), FR-05, SCI-02. Requiere verificación humana antes de una publicación oficial (la publicación oficial lo exige). | Sí |
| D-08 | Campos extra en la respuesta | Además del envelope canónico se devuelven `request_hash`, `schematic_cycle`, `thermal_stages`, `result_status`, `explanation`, `material`, `initial_condition`, `dataset_contains_unreviewed_content`. `protocol` se devuelve aunque esté en borrador (con `review_status`) para mostrar el medio fijo; `protocol_version` es `null` mientras no esté publicado. | FR-07 exige mostrar el medio; doc 06 §16.4 permite campos adicionales sin cambiar los nombres canónicos. | Sí |
| D-09 | Dominio vs. estructura | Fuera de 0–1600 °C o 0–1440 min ⇒ HTTP 422. Fuera del dominio publicado o por encima del límite físico ⇒ HTTP 200 con `simulation_status=invalid_input` y motivo. | Doc 06 §16.2 y SCI-02. | Sí |
| D-10 | Revenido | Se exige `hardened=true` documentado en la condición inicial; no se encadena con un temple previo de la app (P2 pendiente). | Doc 04 §2 y SCI-05. | Sí |
| D-11 | Autenticación admin | JWT de Supabase verificado en servidor (JWKS o HS256), membresía y rol en `admin_memberships`. Para desarrollo local, `scripts/dev_admin_token.py` firma un token con un secreto local; **no existe endpoint de login de desarrollo**. Token solo en memoria del navegador. | Doc 06 §9 y §16.6. | Sí |
| D-12 | Roles | `editor` crea/edita borradores; `reviewer` revisa, publica y revierte; `admin` además gestiona membresías. Revisor distinto del editor configurable (`REQUIRE_DISTINCT_REVIEWER`), apagado por defecto porque hoy hay una sola persona. | Doc 03 §4 y doc 06 §16.6 difieren en quién publica; se eligió el rol de revisión (más seguro). | Sí |
| D-13 | Publicación | Una edición vuelve a `draft`; publicar es crear una *release* inmutable (trigger en BD) que pasa lo revisado a `published`. Revertir = activar una release anterior. | Doc 05 §14.6. | Sí |
| D-14 | Tutor IA | Apagado por defecto. Si se activa: SDK oficial `anthropic`, salida JSON con esquema, validación de citas y de cifras (ninguna cifra que no esté en el contexto) y presupuesto diario; ante cualquier fallo, explicación editorial. Modelo por defecto configurable (`AI_MODEL`). | Doc 11. El propietario no tiene presupuesto de API: no se hace ninguna llamada de pago sin configuración explícita. | Sí |
| D-15 | Flutter 3.50 y `material_ui` | Flutter 3.50 separó Material en el paquete `material_ui`; todo el código lo usa en vez de `package:flutter/material.dart`. | Plantilla oficial de `flutter create` en esta versión. | Sí |
| D-16 | Estado y rutas | Riverpod 3 (una sola solución de estado) + go_router. | Doc 03 §8, doc 07 §4. | Sí |
| D-17 | Microscopio | No se incluye ninguna micrografía: ninguna fuente candidata tiene licencia y correspondencia verificadas para los tres materiales. El visor (zoom digital limitado a 4×, escala solo si calibrada) funciona cuando el admin publique una. | Doc 04 §6, doc 12 §5. | Sí |
| D-18 | Diagramas TTT/CCT/Fe–C | No se dibuja ninguna curva; existen tablas `diagram_sets/diagram_curves` y la sección «Diagramas» explica los conceptos. | Doc 05 §6, doc 07 §7. | Sí |
| D-19 | Contratos compartidos | Fuente única: enums Python → `packages/contracts/enums.json`, `openapi.json` y `contract_enums.g.dart` generados por `scripts/gen_contracts.py`; una prueba falla si quedan desincronizados. | Doc 06 §16.1. | Sí |
| D-20 | Persistencia de simulaciones | Desactivada (tablas creadas, sin escritura). Historial y favoritos solo en el dispositivo. | Doc 03 §6, ADR-005. | Sí |
| D-21 | Valores iniciales del formulario | 20 °C y 0 min: no se sugiere ninguna «receta». | Doc 10 §7 (850/30 son texto de maqueta). | Sí |
| D-22 | Logros y modo docente (P2) | Implementación mínima local: logros desactivables y códigos de actividad que solo codifican la configuración (no autentican, no identifican). | Doc 09 §8, FR-20, FR-22. | Sí |
